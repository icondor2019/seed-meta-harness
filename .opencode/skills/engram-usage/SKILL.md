# Engram operational memory

Search with concrete project and topic terms before repeating past investigation.
Retrieve the relevant observation before relying on a search snippet. Treat memory
as historical evidence and verify it against the current repository when necessary.

Save reusable debugging findings, gotchas and decision rationale with a concise
title, project identity and enough context to explain what happened, why and the
evidence. Prefer updating an existing topic to duplicating the same finding.
Never save credentials, full transcripts or entire SDD artifacts.

Follow the current role contract: in this repository Archivist persists selected
knowledge; other specialists record candidates in their assigned memory.md.
This skill does not authorize otherwise prohibited writes or change workflow gates.

Keep current architecture and setup documentation in curated project docs; keep
operational experience in Engram. Do not claim remote synchronization or successful
persistence without checking the outcome. If unavailable, retain candidates and
report the limitation. Installation is in `docs/tools/windows.md`.

Sources: https://github.com/Gentleman-Programming/engram and
https://github.com/Gentleman-Programming/gentle-ai/blob/main/docs/engram.md.
Use the tool descriptions exposed by the installed version as the API contract.
